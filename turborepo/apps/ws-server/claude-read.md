# Full Session Summary: User-Scoped Vector Store Implementation

## What We're Building

Migrating from provider-scoped `LocalVectorStore*` models to user-scoped `UserStore*` models. One store per user (keyed by `@@unique([userId, storeName])`), provider-agnostic. A document gets indexed once regardless of which provider conversation triggered it. `originatingProvider`/`originatingModel` become metadata, not routing keys.

## Architecture

- **Schema:** `packages/db/prisma/schema/userstore.prisma` — 4 models (`UserStore`, `UserStoreDoc`, `UserStoreDocAnnot`, `UserStoreDocChunk`) + 6 enums
- **SQL:** 6 typed SQL files in `packages/db/prisma/sql/` for pgvector search and raw INSERT/UPDATE operations
- **Service:** `PrismaUserStoreService` in `apps/ws-server/src/prisma/user-store.ts` extends `PrismaLocalStoreService`
- **Types:** Singleton types in `packages/types/src/types.ts`, service types in `apps/ws-server/src/prisma/types.ts`
- **Embedding:** Voyage Multimodal 3.5 (`voyage-multimodal-3.5`), 1024-dim vectors, pgvector HNSW index with `vector_cosine_ops`

## Phase 1: COMPLETE — SQL Files + Migration

### 6 SQL files created in `packages/db/prisma/sql/`:

1. **`searchUserStoreChunksByStore.sql`** — Primary cosine similarity search across all chunks in a store. JOINs `UserStoreDoc` for `originatingModel`/`originatingProvider`. Filters: `READY` chunks, `ACTIVE` docs, non-null embeddings, score >= threshold. Returns 20 columns including `hasVisualContent`, `pageStartOffset`, `pageEndOffset`.

2. **`searchUserStoreChunksByDoc.sql`** — Scoped search within a single doc's chunks. Same pattern but WHERE on `docId` instead of `storeId`.

3. **`insertUserStoreDoc.sql`** — 21-param upsert. ON CONFLICT `attachmentId` (unique). Smart state CASE: re-queues FAILED docs to QUEUED, preserves current state otherwise. Returns `{ id, provenanceId, state, attachmentId }`.

4. **`updateUserStoreDocState.sql`** — 11 params. Updates doc state + extraction metadata. Conditional `indexedAt = NOW()` on ACTIVE. COALESCEs optional fields. Adds `visualMediaSource`/`visualMediaContent` (2 new params vs local equivalent).

5. **`updateUserStoreChunkState.sql`** — 7 params (was 5). Updates chunk state + writes embedding vector. Adds `retryCount`, `hasVisualContent`. Returns `{ id, state, tokenCount, retryCount }`.

6. **`insertUserStoreDocAnnot.sql`** — NEW (no local equivalent). Single annotation insert with rect as 4 individual floats → `ARRAY[]::float8[]`. ON CONFLICT DO NOTHING for idempotency.

## What's Next: Add `resolveAnnotationOffsets` + Pre-computed Fields

### Context

PDF annotations from pdfdown have bounding box coordinates (`rect: [x1, y1, x2, y2]`) but no character offsets. The `UserStoreDocAnnot` schema requires `startOffset: Int` and `endOffset: Int` (non-nullable). With the new `pageBoxes` API on pdfdown metadata, we now have actual page dimensions to do rect-based interpolation of character positions.

All pre-computed fields (`extractedTextLength`, `imageCount`, `imagePages`, `annotPages`, `tokenCount`, nested `annots`) have already been added to `upsertUserStoreDoc`. The remaining work is the offset resolver that enriches raw pdfdown annotations with character offsets.

### File to Modify

`apps/ws-server/src/prisma/user-store.ts` — all new methods on `PrismaUserStoreService`

### New Import

### Methods to Add

#### 1. `resolveAnnotationOffsets` (public)

Main entry point. Synchronous (pure CPU computation + Levenshtein calls).

```ts
public resolveAnnotationOffsets(
  structuredText: StructuredPageText[],
  annotations: PageAnnotation[],
  pageBoxes: PageBox[]
): Array<{
  subtype: $Enums.AnnotSubtype;
  uri: string;
  rect: number[];
  startOffset: number;
  endOffset: number;
  pageNumber: number;
  isCdnLink: boolean;
  linkedDocId: string | null;
  attachmentId: string | null;
}>
```

Algorithm:
1. Build page dimensions map from `pageBoxes` (dominant entry = default, non-dominant override specific pages)
2. Build page offset map from `structuredText` (rolling sum of `body.length` + `\n\n` separator between non-empty pages — matches embedding pipeline in `vector-store.ts:246-248`)
3. Build concatenated text string for Levenshtein search window
4. For each annotation:
   - **Y interpolation**: `yMid = (rect[1]+rect[3])/2`, `relativeY = (pageHeight - yMid) / pageHeight`, `approxStart = globalStart + round(relativeY * bodyLength)`
   - **Levenshtein refinement** (if URI exists and label >= 3 chars): slide a window of `searchLabel.length` across ±200 chars around `approxStart`, track minimum LD. Use refined position if confidence (`1 - bestLD/labelLen`) > 0.5
   - **EndOffset**: from Levenshtein match span, or fallback to `startOffset + labelLength`, or rect X-span heuristic
   - **Clamp** to page bounds
   - Map `subtype` to `$Enums.AnnotSubtype` via `.toUpperCase()`
   - Detect CDN links via `uri.includes("assets.aicoalesce.com")`

#### 2. `buildPageDimensionsMap` (private)

Takes `PageBox[]`, returns `{ defaultDims: { width, height }, overrides: Map<number, { width, height }> }`.
- Dominant entry (`pages` absent) → `defaultDims`
- Non-dominant entries → populate `overrides` map
- Fallback: US Letter `612×792` if somehow no dominant entry

#### 3. `buildPageOffsetMap` (private)

Takes `StructuredPageText[]`, returns `Map<number, { page, globalStart, globalEnd, bodyLength }>`.
- Filter to non-empty body pages (`p.body.trim().length > 0`)
- Sort by page number
- Rolling accumulator: separator = `i > 0 ? 2 : 0` (for `\n\n`)
- Uses `body.length` (UTF-16 code units) matching JS string indexing

#### 4. `extractSearchLabel` (private)

Takes URI string, returns filename/path segment suitable for text search.
- Parse URL, take last path segment
- URL-decode, strip common extensions (`.pdf`, `.png`, etc.)
- Return `null` if result < 3 chars

#### 5. `refineOffsetWithLevenshtein` (private)

Sliding window search using `this.extractor.calculateLD`.
- Window: `concatenatedText.slice(max(0, approxStart-200), min(len, approxStart+200+labelLen))`
- Slide candidate of `labelLen` across window, compute LD for each
- Early exit on exact match (`ld === 0`)
- Returns `{ start, end, confidence }`
- Performance: ~400 positions × LD on ~30-char strings ≈ negligible per annotation

#### 6. `mapAnnotSubtype` (private)

`subtype.toUpperCase()` with validation against known enum values. Unknown → `"LINK"` fallback.

### Edge Cases

| Case | Handling |
|------|----------|
| Annotation on empty-body page | Offset `0, 0` — page not in offset map |
| No URI, dest, or content | Skip Levenshtein, use rect-only |
| Unknown subtype string | Map to `"LINK"` fallback |
| Search label < 3 chars | Skip Levenshtein, use rect estimation |
| Degenerate rect (zero area) | Clamp `relativeY` to `[0, 1]` |
| Single pageBox (uniform PDF) | All pages use default dims |
| CDN link (compat pattern) | `isCdnLink: true`, `attachmentId` extractable from URL path directly — fast resolve |
| CDN link (original pattern) | `isCdnLink: true`, requires indexed DB lookup on `cdnUrl`/`compatCdnUrl` — resolved async |

### CDN Link Resolution (Background / Parallel)

This runs **post-upload in the background**, not in the hot path on send.

#### CDN URL Anatomy — Two Patterns

**Pattern 1: `cdnUrl`** (original upload)
```
https://assets.aicoalesce.com/{origin}/{userId}/{epoch}-{filename}
https://assets-dev.aicoalesce.com/{origin}/{userId}/{epoch}-{filename}
```
- Origins: `upload` | `generated` | `pasted`
- userId: cuid-like string (e.g., `nrr6h4r4480f6kviycyo1zhf`)
- Epoch-filename: `{unixMs}-{originalFilename}` (e.g., `1769736531250-claudception.pdf`)

**Pattern 2: `compatCdnUrl`** (converted format)
```
https://assets.aicoalesce.com/{origin}/converted/{attachmentId}.{ext}
https://assets-dev.aicoalesce.com/{origin}/converted/{attachmentId}.{ext}
```
- Second path segment is `converted` (NOT userId)
- Filename IS the attachment ID directly (e.g., `att_bnlvc59g1kxbhf8jvtv5kxiv.pdf`)
- No epoch timestamp
- **Shortcut**: extract `attachmentId` directly from the URL path — no DB lookup needed!

**Subdomains**: `assets` (prod) | `assets-dev` (dev) — use `this.isProd` to determine

Both `cdnUrl` and `compatCdnUrl` are **indexed** on `Attachment` (schema lines 128-129).

#### Architecture: Two-Phase Approach

**Phase A** — `resolveAnnotationOffsets` (sync, in the extraction flow):
- Computes character offsets via rect interpolation + Levenshtein
- Detects CDN links by checking URI against `assets.aicoalesce.com` / `assets-dev.aicoalesce.com`
- Sets `isCdnLink: true` on matches, leaves `linkedDocId` and `attachmentId` as `null`
- Returns enriched annots → passed to `upsertUserStoreDoc` nested create

**Phase B** — `resolveAnnotCdnLinks` (async, background/void):
- Takes annot records where `isCdnLink === true`
- Parses CDN URLs into fragments: `{ origin, userId, epochFilename }`
- Checks cache first, then DB lookup via indexed `cdnUrl` / `compatCdnUrl`
- If Attachment found, checks for linked `userStoreDoc` → sets `linkedDocId`
- Updates annot records in-place via `prismaClient.userStoreDocAnnot.update()`
- Can run as fire-and-forget (`void`) or awaited

#### New Methods for CDN Resolution

##### 7. `parseCdnUrl` (private)

```ts
private parseCdnUrl(uri: string):
  | { kind: "original"; subdomain: string; origin: string; userId: string; epoch: number; filename: string }
  | { kind: "compat"; subdomain: string; origin: string; attachmentId: string; ext: string }
  | null
```

- Validates against `assets(-dev)?.aicoalesce.com`
- Splits path: `/{origin}/{second}/{third}`
- If `second === "converted"` → **compat pattern**: `attachmentId` is `third` minus extension (e.g., `att_bnlvc59g1kxbhf8jvtv5kxiv`). No DB lookup needed!
- Otherwise → **original pattern**: `second` is userId, `third` is `{epoch}-{filename}`
- Returns `null` for non-CDN URLs

##### 8. `cdnUrlCache` (property)

```ts
public readonly cdnUrlCache = new Map<
  string,  // full CDN URL
  { attachmentId: string; userStoreDocId: string | null }
>();
```

Lazily populated as CDN URLs are resolved. Prevents repeated DB lookups for the same URL across documents.

##### 9. `resolveAnnotCdnLinks` (public, async)

```ts
public async resolveAnnotCdnLinks(
  annotIds: { id: string; uri: string }[]
): Promise<void>
```

For each annot with a CDN URI:
1. **Parse URL** via `parseCdnUrl(uri)`
2. **Compat pattern** (`kind === "compat"`): attachment ID is in the URL path — set `attachmentId` directly, then look up `userStoreDoc` by `attachmentId` for `linkedDocId`. Very fast — no search needed.
3. **Original pattern** (`kind === "original"`): check `cdnUrlCache` → if miss, `prismaClient.attachment.findFirst({ where: { OR: [{ cdnUrl: uri }, { compatCdnUrl: uri }] } })`. Both fields are indexed.
4. If Attachment found → check `attachment.userStoreDoc?.id` for `linkedDocId`
5. Populate cache, then `prismaClient.userStoreDocAnnot.update({ where: { id }, data: { linkedDocId, attachmentId } })`

**`compatStatus` determines which URL pattern you're dealing with:**
- `"ALIASED"` → standard `cdnUrl` pattern. All compat fields exist but are dupes of the normal fields. Use `att.cdnUrl`, `att.mime`, `att.ext`.
- `"ACTIVE"` → compat `compatCdnUrl` pattern with attachment ID in URL path. Use `att.compatCdnUrl`, `att.compatMime`, `att.compatExt` for metadata. This is the output of the post-processing pipeline (image normalization + Adobe webhook for office→PDF conversion).

Dev/prod awareness: the URI in the PDF will contain the actual subdomain used at creation time. The DB `cdnUrl` field stores the same URL. No translation needed — just match directly.

Note: Existing utility methods in `utils.ts` (lines 143-151, 292-300) already handle the `compatStatus` branching for URL/mime/ext selection. Reuse `urlExtWorkupEmbeddings` pattern where applicable.

### Call Site Integration

Runs post-upload in background, not in the hot send path:

```ts
// 1. Extract (Rust, ~80ms)
const [structuredText, images, annots, meta] = await Promise.all([
  pdfDown.structuredTextAsync(),
  pdfDown.imagesPerPageAsync(),
  pdfDown.annotationsPerPageAsync(),
  pdfDown.metadataAsync()
]);

// 2. Resolve offsets (sync, CPU-bound)
const resolvedAnnots = this.prisma.resolveAnnotationOffsets(
  structuredText, annots, meta.pageBoxes
);

// 3. Upsert doc with annots (creates annot records with linkedDocId=null)
const doc = await this.prisma.upsertUserStoreDoc({
  ...baseParams,
  extractedTextLength: structuredText
    .filter(p => p.body.trim().length > 0)
    .map(p => p.body).join("\n\n").length,
  imageCount: images.length,
  imagePages: imagePages.length > 0
    ? this.prisma.collapsePageRefEnumerable(imagePages) : null,
  annotPages: annotPages.length > 0
    ? this.prisma.collapsePageRefEnumerable(annotPages) : null,
  tokenCount: 0,
  annots: resolvedAnnots
});

// 4. Fire-and-forget CDN link resolution (background)
const cdnAnnots = resolvedAnnots.filter(a => a.isCdnLink);
if (cdnAnnots.length > 0) {
  // Fetch created annot IDs, then resolve in background
  void this.prisma.resolveAnnotCdnLinks(cdnAnnotIds);
}
```
